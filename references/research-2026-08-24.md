# Research · Burn Before Reset · 2026-08-24

## Executive judgment

The idea is worth building, but the defensible product is not a token burner. It is a local work-recovery planner with a hard deadline guard. The initial discussion's strongest differentiation survives source review: cross-source work archaeology and bounded queue selection. Its weakest claim is absolute billing safety; local code cannot prove or control all server-side Credits behavior.

Recommended v0.1: strict plan-first candidate, sequential local Codex pilot, no quota scraping, no API keys, no provider fallback, no Cloud Task, no source writes, and no release claim before real-run evidence.

## Findings

### 1. A Skill alone is insufficient

Official Skill documentation explicitly supports scripts and references, so packaging deterministic mechanics with the workflow is native. The deadline must live outside the model's reasoning loop. A Skill can require the guard, but only a process supervisor can signal the worker group.

### 2. `codex exec` is a viable worker adapter

Official documentation establishes JSONL event output, explicit sandbox selection, ephemeral sessions, and structured output. Those are sufficient for a bounded local adapter. The project deliberately does not use the dangerous sandbox-bypass flag.

### 3. Write isolation is stronger than read isolation

The documented `read-only` and `workspace-write` modes describe command-write boundaries, not a narrow source read allowlist. Therefore, the deterministic indexer can guarantee its own allowlist, but the same guarantee cannot be extended to an autonomous Codex Worker without additional OS confinement. This is the main blocker to claiming unattended production safety.

### 4. Nightshift overlaps execution, not work archaeology

Nightshift already provides scheduled multi-project tasks, budget calibration, task selection, branch/PR outputs, providers, and morning summaries. At the inspected commit, its Codex adapter defaults to `--dangerously-bypass-approvals-and-sandbox`, while its public configuration exposes the same bypass. Burn Before Reset should differentiate through fail-closed billing assertions, plan-first cross-source archaeology, frozen queue, explicit hard-stop deadline, and no integration/push.

### 5. CodeBurn overlaps observability, not task selection

CodeBurn parses many local agent session formats, models token/cost/quota views, and includes optional guard hooks. It is a useful architectural reference for structural Codex JSONL parsing and provenance-tagged quota estimates. Burn Before Reset should not duplicate its dashboard or invent quota estimates. A future integration can consume a documented local export only after a separate decision.

### 6. The `aiuse` claim is not load-bearing

The supplied discussion named `aiuse`, but source discovery did not identify a sufficiently authoritative matching repository. The project therefore removes `aiuse` from its formal differentiation table until a canonical source is supplied.

## Product boundary after research

| Capability | Nightshift | CodeBurn | Burn Before Reset v0.1 |
|---|---|---|---|
| Scheduled repo tasks | Yes | No | No; one bounded run |
| Cross-source work archaeology | Limited project/task model | Session analytics | Yes, plan-first |
| Usage/cost dashboard | Budget-oriented | Core product | No |
| Frozen evidence-linked queue | Not the central contract | No | Core contract |
| Absolute user deadline guard | Time windows/timeouts | Budget hooks | Core local guard |
| Default source mutation | Branch/PR work | Read/optional settings actions | No source writes |
| Billing guarantee | No | No | Explicitly not claimed |

## Verification claims permitted after this build

- `candidate`: files and tests exist.
- `verified`: structure, deterministic tests, historical replay, forward test, and repository fresh-process discovery pass.
- `released`: only after exact installation/publishing approval and new-process verification in every target harness.
- `portable`: only after at least three real successful tasks and promotion approval.

## Unverified ledger

- Exact Help Center UI fields and server-side behavior for Credits/Auto top-up could not be extracted programmatically on 2026-08-24; user assertions remain mandatory but are not proof.
- Project-specific read confinement for Codex Worker is not established by current official sandbox documentation.
- Long-running behavior under an actual quota reset is not tested in this build.
- `aiuse` canonical repository and product claims remain unidentified.
